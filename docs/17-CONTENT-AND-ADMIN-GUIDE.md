# 17. Content and Admin Guide

Content quality is the product. This doc defines how problems, tests, quizzes, packs, and roadmaps are authored, validated, versioned, and published (feature **X7**, **D1**, **D4**, **D5**, **C1**, **C2**, **P3**, **P4**, **I2**).

## 1. Content sources and licensing

- **Original problems** written for PrepQuest (preferred).
- **Classic algorithmic problems** (public domain concepts like two-sum, BFS shortest path) rewritten in original wording with original examples.
- **No scraping** or copying of statements/editorials from commercial platforms. Company tags are curated metadata ("pattern seen in public reports"), not copied question text.
- Each problem has `source` and `license` fields; reviewers verify before publishing.
- Third-party datasets (SQL) must have permissive licenses recorded.

## 2. Repository layout (`content/`)

```

├─ problems/

│     ├─ hints/{1,2,3}.md
│     ├─ editorial.json       # approaches (code per language, complexity, pitfalls, talk track)
│     ├─ tests/
│     │  ├─ manifest.json     # [{ordinal, kind, label, weight}]
│     │  ├─ 01.in 01.out ...
│     ├─ generators/
│     │  ├─ gen_random.py, gen_max.py, gen_scale.py (for X4)
│     │  └─ validator.py      # input validator vs constraints
│     └─ solutions/

│        └─ mutants/{off_by_one.cpp, tle_bruteforce.cpp, ...}   # expected verdicts in manifest
├─ quizzes/{os,dbms,cn,oop,sql,embedded,ml}.json

```

All content is validated by `pnpm content:validate` (JSON Schemas) and imported by `pnpm content:import` (idempotent upsert by slug + version).

## 3. Problem authoring workflow (Admin → Draft → Review → Publish)

1. **Draft**: author writes statement, constraints, examples, signature, tags, patterns, estimated time, difficulty.
2. **Starter code and drivers**: generate from signature; check each language compiles with a stub.
3. **Reference solutions** in all supported languages (at least C++ and Python; Java before publish).
4. **Tests**:
   - Samples (match statement examples).
   - Hidden functional tests (≥ 10 for Easy, ≥ 15 Medium, ≥ 20 Hard).
   - Edge-labeled tests (empty, single, duplicates, negative, max values, sorted/reverse-sorted, all-equal, disconnected graph, cycles).
   - Stress tests at max constraints (≥ 2).
   - **Validator** run on every input (reject constraint violations).
   - Expected outputs generated by reference solution; cross-checked with a second independent solution (or brute force on small inputs).
5. **Limits**: reference time × 3 (min 1 s), memory 256 MB default; language multipliers applied automatically; verify reference passes with margin ≥ 2x on slowest language.
6. **Mutation check**: run mutants; each must produce its expected verdict (WA/TLE/RE). Publishing blocked otherwise.
7. **Hints (3 tiers)**: nudge, technique, pseudocode. Reviewer verifies no spoilers in tier 1 and no code in tier 3.
8. **Editorial**: ≥ 2 approaches where applicable (brute force, optimal), complexity with justification, pitfalls, follow-ups, interview talk track.
9. **Review** by a second person using the checklist below.
10. **Publish** → version 1 live; changes create new versions; test changes trigger **rejudge** option for affected AC submissions (admin chooses: rejudge all / keep).

### Reviewer checklist

- [ ] Statement unambiguous, constraints complete, examples correct.
- [ ] Difficulty and tags plausible; patterns present.
- [ ] Tests cover edge classes; validator passes; mutants fail properly.
- [ ] Limits sensible; brute force fails big tests when intended.
- [ ] Hints are graduated; editorial correct; code compiles/passes.
- [ ] Original wording and license/source recorded.
- [ ] Time estimate and company tags justified.

## 5. Quiz and aptitude authoring

- One concept per question; distractors plausible; explanation states why wrong options are wrong.
- Tags: subject, topic, difficulty (1 to 5), type, estimated seconds.
- Include `interview_line`: how to answer the same concept verbally in 20 seconds.
- Code-output questions are verified by actually running the code in the judge (admin tool).
- CSV import template provided; import produces a review queue before publishing.
- Aptitude items include `shortcut_md` (speed trick) and `est_seconds` to enable realistic OA timing.

## 7. Roadmap schema

Nodes with `topic_slug`, `prerequisites[]`, `problem_ids[]` (ladder: easy → medium → hard), checkpoint quiz, resources, thresholds. **DAG validation** on save (topological sort must succeed).

## 8. Admin panel details (X7)

### Modules and screens

1. **Dashboard**: queue depth, judge health, LLM spend, new signups, open integrity flags, content in review.
2. **Problems**: list/filter by status; editor with live preview; tabs: Meta, Statement, Starter/Drivers, Tests, Checker, Limits, Hints, Editorial, Solutions/Mutants, Versions, Validation.
3. **Validation panel**: checklist with live pass/fail (validator, reference runs, cross-check, mutants, time margin, hints present, editorial present).
4. **Test manager**: upload zip, paste, generate with seeds, labels, reorder, hide/show, size warnings, diff vs previous version, rejudge impact estimator.
5. **Sheets / roadmaps / tags / companies**: drag-and-drop, DAG validator, orphan checks.
6. **Quizzes / aptitude / SQL / questions**: grid editor, CSV import, review queue.
7. **Company packs**: JSON editor with schema validation and "preview interview plan".
8. **Contests**: create, assign problems, scoring, freeze, announcements, live monitor, rejudge, post-contest integrity.
9. **Users**: search, view activity, suspend/ban, reset 2FA, impersonate (consent banner + audit).
10. **Integrity queue**: flags with evidence (similarity matches side by side, paste timeline), decision workflow (confirm, dismiss, escalate), appeals.
11. **Reports and moderation**: user reports, peer mode abuse, public profile content.
12. **System**: feature flags, config (XP tuning, rate limits, model names, prompt versions), queue controls (pause lane, drain worker), maintenance mode banner.
13. **Audit log**: filter by actor/entity/time; export.

### Roles and permissions

| Role                                                                            | Permissions                                                                                  |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| content_editor                                                                  | Create/edit drafts, submit for review                                                        |
| reviewer                                                                        | Approve/publish content, run validations, rejudge                                            |
| moderator                                                                       | Integrity queue, reports, user suspensions (not deletion)                                    |
| support                                                                         | View users, resend verification, impersonate (with ticket id), data export/deletion handling |

### Audit and safety

- Every write logs `actor, action, entity, before/after diff, IP`.
- Dangerous actions (delete, mass rejudge, impersonation, config change) require confirmation and reason text.
- Admin sessions: 2FA required, short idle timeout (30 min), IP allowlist optional.

## 9. Versioning and rollouts

- Problem version bump when statement, tests, limits, or checker change; old submissions keep their version.
- If tests change: admin chooses **rejudge** (queue bulk lane) or **grandfather**.
- Content releases are tagged (`content-2026.10.1`), importable and reversible.
- Company packs show `last reviewed`; stale (> 6 months) flagged in admin.

## 10. Content QA metrics (post-launch)

- Acceptance rate vs expected difficulty (flag outliers: Easy under 20% or Hard over 70%).
- Median solve time vs estimate.
- Hint tier usage distribution (tier-1 usage extreme suggests unclear statement).
- Report counts per problem ("wrong test", "unclear").
- Quiz item analysis: discrimination index, items with > 90% or < 20% correct reviewed.
- Interview question usefulness ratings.

## 11. As built (Phase 3)

**Authoring.** `pnpm content:new <slug>` scaffolds a folder. Per problem: `meta.json`, `signature.json`, `statement.md`, `constraints.md`, `examples.json` (structured: JSON `args` per parameter and the expected return value), `solutions/ref.py` (class `Solution` with the signature's method), `tests/cases.json` (hand-written edge cases, each labelled) and optionally `tests/gen.py` (seeded generator for random and stress cases, using `content/_lib/gentools.py`). Starter code is generated from the signature unless `starter/<lang>.txt` overrides it; hints go in `hints/{1,2,3}.md`. Editorials and mutant solutions are authored in Phase 5.

**Pipeline.**
1. `pnpm content:build-tests` writes `tests/NN.in|out` and `manifest.json`: samples first (from `examples.json`), then `cases.json`, then `gen.py` output; duplicate inputs are dropped; expected outputs come from running `ref.py` through the harness. Each sample is cross-checked against the answer written in `examples.json`, so a statement that disagrees with its reference solution fails here.
2. `pnpm content:validate` checks schemas, slug/folder match, tag taxonomy, statement/constraints, HTML-free statements, example encoding, starter files, and the test rules (contiguous ordinals, format against the signature, sample/edge/stress kinds and labels, 10/15/20 non-sample tests by difficulty, at least 2 stress tests, size limits).
3. `pnpm content:verify` re-runs every reference solution on every committed input and compares with the committed output.
4. `pnpm content:import [--publish]` upserts problems (tags, three languages with limits, test rows, test files to object storage, hints) and sheets. A content hash (statement, metadata, signature, examples, starters, hints, every test) decides whether a new version is needed; an unchanged problem is a no-op. New problems are drafts unless `--publish` is passed.

**Shipped content:** 20 original problems (10 easy, 8 medium, 2 hard; 19 to 31 tests each, 7 MB total) and the sheet `foundations-20`.

**Admin v0** (`/admin/problems`): list with status and search, create a draft with a signature builder, editor tabs (Meta, Statement with preview and examples, Starters and limits, Tests with zip upload and the current test table, Versions, Audit for reviewers), a "Run checks" checklist, and the workflow buttons permitted for the signed-in role. Not built yet: the test generator runner, rejudge options, diff between versions, hints/editorial editors, mutation checks, and the other admin modules in §8.
